# M1-P4: проверенный журнал результатов v6

**Статус: частичный P4, не релиз карьеры.**

Новый независимый модуль `src/core/m1-v6-result-journal.ts` вводит
`schemaVersion: 2` только для движка `engineVersion: '5'`
и событий `eventSchemaVersion: 6`. Замороженные M0-save-v1 и
исторический журнал результатов v5-v1 не меняются.

- Первоначальный M0-снимок проверяется по текущим строгим правилам.
- Повторно проверяются careerId, revision, идентичность синтетической
  базы и разрешённая фикстура по исходному круговому календарю.
- Результат v6 реконструируется через авторитетный
  `deriveM1VerifiedV6AppearanceReport` из оригинального prematch,
  назначенной policy, seed и точной последовательности команд.
- После проверки фиксируются счёт, удары, xG, действительные авторы
  синтетических голов, жёлтые карточки, удаления и подтверждённые
  медицинские выбытия, RNG и число событий.
- Дублирующие команды, сыгранные фикстуры и устаревшие ревизии
  отклоняются типизированно; проверенный ввод не изменяется.
- Пакет из 1..16 последовательных матчей возвращается только целиком.
  Поздняя ошибка не отдаёт частично обновлённое состояние.
- Прочитанные старые сводки проверяются структурно, но без полноценного
  повторного воспроизведения: для доказуемой аутентичности истории нужен
  доверенный слой хранения. Внешний persistence-адаптер обязан делать
  атомарный CAS по careerId и revision до записи всей новой ревизии.

**Границы:** это pure-domain transaction proposal, а не готовое
browser persistence. Нет длительностей дисквалификаций, медицинского
прогноза, пенальти, автоголов, остановленных матчей, переноса
физического состояния футболистов на следующие матчи, полноценной
турнирной таблицы или лицензированных составов M2. Эти сведения
не выдумываются и не сохраняются под видом подтверждённых.
