# M1 P4: exact playable source report and atomic career application

This evidence campaign targets existing P4 acceptance criteria on the
same source-driven v188 playable path used by Chrome, Edge and Safari.
It does not introduce a different result generator, a second ledger or
a new persistence schema.

The executable gate covers:

1. A *real 0-0* generated fixture, replayed final report and absence
   of fabricated goals/scorers/own-goals/penalty goals.
2. Eight distinct successive two-team fixtures: immutable previous
   journal, unchanged pre-commit input on rejection, precise source
   attribution, independent condition replay, both-club table updates
   and intact fictional hold inspection without invented KDK clearance.
3. Duplicate command/revision refusal after committed CAS, mutated
   score refusal before CAS, corrupt historical source rejection.
4. An interrupted virtual-time pause with no implicit career revision,
   successful exact source replay and exactly one final application.
5. Existing real-platform full 240-fixture browser CAS/backup and native
   crash/reload workflows remain separately mandatory.

This work is a **candidate for P4 evidence**, not a claim that P4,
P3 or P5 is accepted by a unit test. The parent P1 durable pause PR
must first be accepted and integrated with 0 CI failures; independent
exact-main acceptance and further P4 cross-module review are required.
The 2024/25 holdout remains sealed; no M2/release.
