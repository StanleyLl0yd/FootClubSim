Wikipedia's owner-approved primacy applies to *personnel research* only.

## Source edition and implementation gates

1. **M0:** retain the synthetic source declaration, all versioned wire/save/rules identifiers and the explicit crosswalk above; test generic validation independently from authentic RFU rules. No unlicensed data, external crests, official schedule or match PDFs enter the generated bundle. M0 still needs explicit owner approval of the source/edition matrix and any remaining match-PRNG contract.
2. **M1:** implement only owner-authorized simulation after M0 closes, using new reviewed versioned events, determinism and rights-gated calibration. Do not claim a synthetic match validator is an IFAB-compliant simulator.
3. **M2:** implement a separate **source-edition-pinned RPL/RFU/IFAB rules pack** (registrations, matchday/discipline, standings, sanctions, interruptions and exceptions), with primary articles, applicability dates, amendments and versioned positive/negative rule tests. No generic synthetic limit substitutes for an authentic RFU limit.
4. **All future playable personnel:** Wikipedia revision-pinned research first; independent dated authoritative checks for eligibility and dates; source/data/likeness/rights approval before any pack distribution. Wikidata remains secondary only. Current completeness is 0/16 registered source rosters and 0 cleared playable imported person fact records.

This is an **inventory and design reconciliation**, not an approved legal compliance result, the first/second mandatory complete repository audit, browser exceptional-case acceptance or authorization to start M1.
